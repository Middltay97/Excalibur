# Shipping CountRight to Google Play (C6000 Android scanner)

This guide turns the existing CountRight web app into a real Android app
distributed through the Google Play Store, using a **Trusted Web Activity
(TWA)** wrapper generated by Bubblewrap. Every Lovable deploy updates the
app's content instantly — you only resubmit to Play if you change the
package itself (icons, name, version code).

The published URL is **https://aagcountright.lovable.app** and the manifest
lives at `https://aagcountright.lovable.app/manifest.webmanifest`.

---

## ⚡ MDM deployment (ManageEngine) — use GitHub Actions

If you're deploying to managed C6000 devices via ManageEngine MDM, **don't
run the local script**. Use the CI workflow at
`.github/workflows/android.yml` instead. It produces a signed APK + AAB on
every push to `main` (and on manual dispatch), downloadable from the
Actions run page.

**One-time setup**

1. Generate a signing keystore on your laptop (needs JDK `keytool`):
   ```bash
   keytool -genkeypair -v \
     -keystore countright.keystore -alias countright \
     -keyalg RSA -keysize 2048 -validity 10000 \
     -storepass <PASSWORD> -keypass <PASSWORD> \
     -dname "CN=CountRight, O=AAG, C=US"
   ```
   **Back up `countright.keystore` + password.** Lose them and you can never
   ship an update to the same package — MDM treats a re-keyed APK as a
   different app.

2. Add 4 repo secrets in GitHub → Settings → Secrets and variables → Actions:
   | Secret | Value |
   | --- | --- |
   | `ANDROID_KEYSTORE_BASE64` | `base64 -w0 countright.keystore` |
   | `ANDROID_KEYSTORE_PASSWORD` | your `-storepass` |
   | `ANDROID_KEY_ALIAS` | `countright` |
   | `ANDROID_KEY_PASSWORD` | your `-keypass` |

3. After the first CI run, grab the SHA-256 fingerprint from the
   "Print SHA-256 cert fingerprint" step in the workflow log and paste it
   into `src/routes/[.]well-known.assetlinks[.]json.ts` (replace both
   `REPLACE_WITH_…` placeholders), then **Publish** in Lovable. Without
   this the app will show a Chrome address bar instead of going fullscreen.

**Each release**

- Bump `appVersionCode` (and optionally `appVersionName`) in
  `android/twa-manifest.json`, commit, and push. CI produces a fresh
  `countright-release.apk` artifact. Upload that to ManageEngine →
  App Repository → Add Enterprise App. The package ID is unchanged so it's
  treated as an upgrade.
- Or push a tag `android-vX.Y.Z` to also attach the APK + AAB to a
  GitHub Release.

**On a C6000 in ManageEngine**

1. ManageEngine MDM → App Repository → Add Enterprise App → upload the APK.
2. Create a distribution policy targeting your C6000 device group;
   choose **Silent install** (works because devices are MDM-enrolled).
3. Optionally mark it as a Kiosk / required app so users can't uninstall.

After deploy, verify on a device: launches fullscreen (no Chrome address
bar = assetlinks wired correctly), scanner trigger fires keystrokes, keeps
working with wifi off mid-count.

## Local build (alternative — only needed if you want to build on your laptop)


## What's already done in the codebase

- `public/sw.js` — real service worker. Caches the app shell + static assets
  so `/m` keeps working when wifi drops mid-session.
- `public/manifest.webmanifest` — PWA manifest with `start_url: /m`,
  `display: standalone`, maskable 512 icon. Meets Bubblewrap's PWA criteria.
- `src/routes/[.]well-known.assetlinks[.]json.ts` — server route that
  serves `/.well-known/assetlinks.json` for Digital Asset Links.
  **You must edit it** with the package name + SHA-256 fingerprint
  Bubblewrap prints after the first build (see step 3 below).
- `scripts/build-android.sh` — one-command wrapper that runs the entire
  Bubblewrap flow against the live published manifest.

## Prerequisites (one-time)

1. **Google Play Console developer account** ($25 one-time):
   https://play.google.com/console/signup
2. **Node.js 18+** and **Java JDK 17** on your machine (`java -version`
   should report 17.x). The script installs `@bubblewrap/cli` for you on
   first run.
3. Make sure the latest Lovable changes are **published** (Publish → Update)
   so the script can read the live manifest.

## Step 1 — First-time build (run once)

From the project root:

```bash
./scripts/build-android.sh --init
```

The script will:

1. Verify Node, Java, and Bubblewrap are installed (auto-installs Bubblewrap
   if missing).
2. Confirm `https://aagcountright.lovable.app/manifest.webmanifest` is live.
3. Create `./android-build/` and run `bubblewrap init` against the live
   manifest. Suggested answers:

   | Prompt | Value |
   | --- | --- |
   | Application name | `CountRight` |
   | Application ID (package) | `app.countright.scanner` |
   | Display mode | `standalone` |
   | Status bar color | `#18ABBF` |
   | Splash color | `#0b1220` |
   | Generate signing key | **Yes** — back up `android.keystore` and the password. Losing it means you can never update the app on Play. |

4. Run `bubblewrap build`, producing in `./android-build/`:
   - `app-release-bundle.aab` ← upload to Play Console
   - `app-release-signed.apk` ← sideload onto the C6000
   - `assetlinks.json` ← used in step 3

To target a different URL (e.g. a custom domain) override the env var:

```bash
PUBLISHED_URL=https://countright.example.com ./scripts/build-android.sh --init
```

## Step 2 — Subsequent rebuilds

Bump `appVersionCode` (and optionally `appVersionName`) in
`./android-build/twa-manifest.json`, then run **without** `--init`:

```bash
./scripts/build-android.sh
```

This reuses your existing signing key and manifest answers and just rebuilds
the bundle.

## Step 3 — Wire up Digital Asset Links

Without this the C6000 will show a Chrome address bar at the top of the app.
Open `./android-build/assetlinks.json` and copy the `package_name` +
`sha256_cert_fingerprints` value into:

```
src/routes/[.]well-known.assetlinks[.]json.ts
```

(replace the two `REPLACE_WITH_…` strings), then **Publish → Update** in
Lovable. Verify it's live:

```
https://aagcountright.lovable.app/.well-known/assetlinks.json
```

## Step 4 — Sideload onto the C6000 to test

1. On the C6000: Settings → Security → enable **Install unknown apps** for
   your file manager (or enable USB debugging and use `adb`).
2. Install:
   ```bash
   adb install -r android-build/app-release-signed.apk
   ```
   Or transfer the APK over USB and tap to install.
3. Launch from the home screen and confirm:
   - No Chrome address bar (fullscreen)
   - Scanner trigger feeds keystrokes into inputs
   - Camera barcode scanning works
   - App keeps working with wifi off mid-count

If you see an address bar, `assetlinks.json` is missing, not yet deployed,
or the package name / fingerprint don't match. Re-check step 3.

## Step 5 — Submit to Play Store

1. Play Console → **Create app**.
2. **Internal testing** track: upload `android-build/app-release-bundle.aab`,
   add yourself as a tester, install via the opt-in link on the C6000,
   smoke-test again.
3. Fill out the store listing (title, descriptions, screenshots from the
   C6000, 512 px icon, 1024×500 feature graphic).
4. Complete content rating, target audience, data safety.
5. Promote internal → production.

First review typically takes 1–7 days.

## Updating later

- **Web/UI changes**: just publish in Lovable. Devices pick up the new
  build the next time the app launches with internet (the service worker
  fetches fresh HTML, then caches it).
- **Package changes** (new icon, new name, permissions): bump
  `appVersionCode`, run `./scripts/build-android.sh`, upload the new
  `.aab` to Play.

## Troubleshooting

- **`Cannot fetch …/manifest.webmanifest`**: publish in Lovable first.
- **App opens in Chrome instead of standalone**: `assetlinks.json` not
  reachable, or wrong package name / fingerprint.
- **Stale content after publish**: open the app twice — the service worker
  applies the new shell on the second launch. To force-refresh during
  testing: Settings → Apps → CountRight → Storage → Clear cache.
- **Java errors during build**: ensure JDK 17 (not 11 or 21). Set
  `JAVA_HOME` accordingly.
